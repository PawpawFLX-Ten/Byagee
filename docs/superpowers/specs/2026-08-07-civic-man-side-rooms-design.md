# Civic Man — 随机开门连新房（Side Rooms）设计稿

**日期:** 2026-08-07
**状态:** 待审
**目标:** 修正空间事件设计——所有事件统一为「开门 + 连接新房子」，方向随机不写死；「扩建改造」都在新房子内实现，不再原地改主厅；场景补齐新房间的墙、门洞与门视觉。

## 二、新机制

### 2.1 事件 = 开门 + 连新房

每次空间事件：从某个房间的**可用外墙方向**随机选一侧（东/西/南/北），在该墙开一扇门（可闩、参与声学），连接一个新房间。不再有任何主厅原地变形事件。

### 2.2 方向选择（纯函数，可测）

```ts
type Side = 'east' | 'west' | 'north' | 'south'
```

- `sideAabb(room, side, w, d)`：按方向外推新房 AABB，与源房间共享墙，保留 1m 间隙（防路径/视觉贴合）。
- `availableSides(layout, roomId)`：四侧依次检查外推 AABB 是否与任何现有房间/障碍 AABB 重叠（含橱柜）——重叠即不可用。
- `pickConnection(layout, rng)`：**优先主厅 r0**；r0 无可用方向 → 按加入顺序找第一个有可用方向的房间；全部房间无可用方向 → 返回 `null`（事件降级为大厅微调兜底，见 2.6）。
- `addRoomConnectedAt(layout, room, openingId, fromRoomId, side)`：门位置按方向放在共享墙段中点：
  - east:  `x = from.max[0]`，`z = 共享墙段 z 中点`
  - west:  `x = from.min[0]`
  - north: `z = from.min[1]`（-z），`x = 共享墙段 x 中点`
  - south: `z = from.max[1]`（+z）
- 门位置与橱柜障碍重叠时：移除该橱柜（门取代它）。

### 2.4 调度不变

- 事件触发链不变（首 Boss 击败 → 首事件；之后 Boss 击败 + 冷却 120s；inter-boss C5 minor morph 最多 1 次）。
- `EVENTS` 表 ID、池、权重保持；注释更新。
- A4/C4 维持 `DEFERRED_UPSTAIRS` 禁用。

### 2.5 场景（视觉补齐）

- **Room**：为**所有房间**渲染四面墙（含 r0 原有逻辑）；每面墙若该边有 opening，则在门位置断开为两段（墙洞），宽度 = 门宽（~1.4m）。新房间地板沿用现有逻辑（floor 0 与楼上颜色）。
- **Door**：改为读 `layout.openings` 渲染每扇门（含朝向 rotation：east/west 门绕 Y 旋转 90°），保留北门（主门，写死渲染逻辑保留或转为 opening）。沿用现有门框/门板/对联模型。
- 橱柜障碍：被门取代的橱柜同时从视觉移除（障碍列表驱动，自动生效）。

### 2.6 兜底

- 所有房间均无可用方向（理论上 ≤9 个方向位）时，事件**降级**为「微调」：沿用现有 C5 挪障碍逻辑，不新增房间，toast 仍显示事件名。保证事件永远生效、无 404 状态。


## 四、约束

- 不触碰威胁数值、门禁、声学、追杀客、Boss 逻辑。
- 不改已有桌型/贴图；全纯几何。
- 方向选择与门位置为纯函数，Vitest 覆盖。

## 五、测试

- `spaceLayout.test.ts`：`sideAabb` 四方向外推正确；`availableSides` 占用方向排除（含障碍、橱柜）；`addRoomConnectedAt` 门在共享墙段中点（四方向各断言坐标）；橱柜重叠时移除。
- `spaceApply.test.ts`：A1/A2/A3/A5 在四方向各应用一次 → 房间 AABB 不重叠、门数正确（A2 两门）、座位/障碍正确；C1–C6 新房版内容断言；无方向时降级微调。
- `spaceDirector.test.ts`：池/权重不变，A4/C4 禁用。
- `quality.test.ts`：长局模拟注入随机方向事件不破坏不变量（座位数、房间数、pathing）。

## 六、超出范围

## 七、成功标准

1. 多次事件后，主厅东/西/南/北四面都出现过新房（随机分布，不写死）。
2. 新房间有墙、有门洞、有朝向正确的门；被取代的橱柜消失。
3. 事件不再改动主厅 AABB；C 类内容全部在新房内。
4. 所有方向位用尽时事件降级微调不报错。
5. 测试全过、lint/build 通过。
